\section{Purpose and assurance model}

GL1F makes a deliberately narrow model family unusually easy to inspect. A
complete fixed-depth tree is serialized as fixed-width integers. The EVM
runtime performs no floating-point arithmetic and no data-dependent recursion:
it reads a feature index and threshold, applies one strict comparison, updates
a heap index, reads one leaf, and accumulates an integer. The same core is
consumed by browser, native, and contract evaluators.

The supplement establishes five different claims, each with its own evidence:

\begin{enumerate}
  \item \textbf{Representation:} exact byte geometry follows from the complete
        tree layout.
  \item \textbf{Traversal:} a depth-$d$ tree reaches exactly one valid leaf
        after exactly $d$ decisions.
  \item \textbf{Reconstruction:} a well-formed GL1C manifest returns the exact
        serialized primitives, including chunk-boundary reads.
  \item \textbf{Equivalence:} identical externally verified canonical bytes
        and packed int32 input produce the same integer scalar or vector under
        conforming local and EVM evaluator specifications. Source inspection
        and finite tests separately support the tested contract path.
  \item \textbf{Approximation:} abstract exact-real fixed-point error is
        bounded when saturation and path changes are excluded; the production
        binary64 correction and a split-margin condition make that boundary
        explicit.
\end{enumerate}

Training parity is not promoted to a universal theorem. The trainers use
floating-point split scores, metrics, exponentials/logarithms, and seeded
random choices. Their equality is therefore supported by an explicit
publication profile and executable cross-engine tests.

\section{Executable evidence}

\subsection{Three-engine training parity}

The publication suite invokes the production browser worker under Node,
compiles the production C++ trainer, invokes the Python CLI, and compares the
core GL1F bytes. It covers regression, binary, multiclass, and multilabel
objectives; linear and quantile binning; weighting; stratification; early
stopping; fixed-budget refitting; learning-rate schedules; seed zero;
repeatability; v1/v2 inference; rounding boundaries; packaging; and hostile
stream rejection.

The suite identified a real operation-order discrepancy. The browser computed
linear histogram bins by multiplying by a cached reciprocal, while Python and
C++ divided by the range before multiplication. The algebra is real-number
equivalent but not IEEE-754 equivalent at every bin boundary. Replacing the
reciprocal multiplication with the same divide-then-multiply order restored
all tested three-engine byte comparisons.

An additional generated boundary case then exposed a second finite witness. For a
generated 4,000-row, 12-feature, four-class profile, Python accumulated the
softmax denominator from binary32-rounded exponentials while JavaScript and
C++ accumulated binary64 exponentials. One byte in the 22,120-byte Python
core differed, corresponding to a one-Q-unit leaf change. The corrected
profile uses binary64 exponentials, an ascending-class-index binary64
denominator sum, a binary32 numerator, binary64 division, and a binary32
result. All three engines now emit
\nolinkurl{58e3d9e63c5dd1313872e0c5a07c229b071272f1137f393a0384601329a432eb}
for that witness. This is a maintained regression result, not a universal
claim about every platform or mathematical library.

\section{Open-protocol and registry boundary}

GL1F is an open protocol whose model bytes are intentionally public. Paid mode
may meter the canonical transaction/read endpoint, event trail, or integrated
service; it is not model encryption and does not prevent independent local
evaluation.

The deployed registry records a caller-supplied model identifier and manifest
without recomputing the entire core on-chain. This does not invalidate the
canonical publisher or the 12 live records—the strict witness confirms all 12.
It means that arbitrary future entries require the same independent verifier
unless a later registry enforces the binding. The consequence is a
registration-integrity and availability boundary.

\section{Scientific limits and falsifiability}

The format, tests, proofs, NFT, and chain witness do not establish:

\begin{itemize}
  \item predictive accuracy, calibration, external validity, or causal truth;
  \item absence of leakage, sampling bias, data drift, or subgroup harm;
  \item authorship, legal intellectual-property ownership, or licence
        enforceability;
  \item secrecy of model bytes, feature vectors, or outputs;
  \item correctness of an RPC response without the stated node/state
        assumptions; or
  \item suitability for clinical, financial, or other high-stakes use.
\end{itemize}

Application-level claims require dataset provenance, a prespecified evaluation
protocol, baselines, ablations, uncertainty estimates, calibration, and
domain-specific ethical and safety analysis. These materials are outside the
scope of this systems report.

\section{Conclusion}

GL1F's scientific leverage comes from reducing the semantic gap between model
artifact and execution. The tree grammar is fixed-width enough to count, the
integer semantics are simple enough to prove, the three training surfaces are
close enough to test at the byte level, and the published code is open enough
to reconstruct independently. The resulting model is not an oracle of truth;
it is a public computational instrument whose exact behavior can be inspected,
challenged, and deterministically reevaluated under explicit premises.
